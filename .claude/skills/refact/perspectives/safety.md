# データ安全性・パフォーマンス チェック

## チェック項目

- **データが消えるケースが絶対に発生しないこと**を最優先で確認
- Single Source of Truth に準拠した設計になっているか
- アプリ起動時に限らず、各種画面を開いた際やユーザーの操作時のパフォーマンスは最適化されているか
- 後方互換性の取れている実装になっているか（データベースとアプリバージョンの関連）
- 各種データの保存方法は最適か（UserDefaults、Core Data など）
- 初期化ユーザー / 長期ユーザーそれぞれに対して問題なく機能するか
- 一部データが不足しているパターンやデータ量が多くロードに時間がかかるエッジケースへ対応できているか
- データの保存フロー・ロードフローのコアロジックに不具合・デグレが発生していないか
- 不要なデータの書き込み・読み込みロジックがないか

## 過去のレビューで発見された典型的な問題

- **初期値の上書き**: 編集画面でプロパティを `Date()` 等で初期化してしまい、既存データが消失した
- **N 回保存のパフォーマンス問題**: ループ内で個別に保存を呼ぶと、大量データで著しく遅くなる。バッチ更新を検討する
- **Codable プロパティのデフォルト値未設定**: 新規プロパティ追加時にデフォルト値がないと、既存データのデコードが失敗する

## 重点確認

- データ操作の中心となるファイル
- Codable モデルのプロパティ追加時のデフォルト値
- 保存・読み込みロジックの整合性
