# Feature Start: 新機能開発オーケストレーション

要望: `$ARGUMENTS`

このスキルは新機能開発の全工程をオーケストレーションする。
**各フェーズの開始前にユーザーの承認を得てから進行する。**

---

## フェーズ 1: PM — 要件整理＆影響分析

Agent ツールで `pm` エージェント (`.claude/agents/pm.md`) を起動:

1. `$ARGUMENTS` を分析し、要件を明確化する
2. 既存コードを調査して影響範囲を特定する
3. 以下を出力する:
   - 機能概要と仕様詳細
   - 影響範囲マップ（レイヤー × ファイル × 変更内容）
   - タスク一覧（優先度・見積もり付き）
   - リスク・注意点

**ユーザーに提示して承認を得る。承認が得られるまで次のフェーズに進まない。**

---

## フェーズ 2: 設計レビュー

PM の出力を基に、以下を確認する:

1. CLAUDE.md の Architecture に沿った設計になっているか
2. Screen → Presenter → Service → Repository の層構造を守れるか
3. 新規ファイルの配置場所は既存構成に合っているか
4. データモデルの変更がある場合、後方互換性の方針

設計方針をユーザーに説明し、以下を確認する:
- 「この方針で実装を進めてよいか？」
- 「変更したい点や追加の要件はあるか？」

**ユーザーの承認を得てから次のフェーズに進む。**

---

## フェーズ 3: 実装

承認された設計に基づき、CLAUDE.md の Coding Rules に従って実装する:

1. **下位層から実装**: Model → Repository → Service → Presenter → Screen
2. **Coding Rules の遵守**:
   - 強制アンラップ禁止 → `guard let` / `if let` / `??`
   - ハードコード禁止 → `AppConstants`
   - アクセス修飾子を明示
   - ローカライズは `String(localized:)`
   - 1 ファイル = 1 型
3. **ビルド確認**: 実装完了後に `xcodebuild build` を実行
4. **新規ファイルは Xcode プロジェクトに登録**

実装内容のサマリをユーザーに提示する。

---

## フェーズ 4: QA レビュー

Agent ツールで `qa` エージェント (`.claude/agents/qa.md`) を起動し、実装結果を検証:

1. **P0: データ安全性** — データ消失リスク、後方互換性、環境切り替え
2. **P1: 機能整合性** — デグレ、副作用、例外パターン、通知
3. **P2: コード品質** — 強制アンラップ、命名、アクセス修飾子
4. **P3: 設計** — 層構造、依存方向

問題があれば修正し、QA 結果をユーザーに報告する。

---

## フェーズ 5: デザインレビュー

Agent ツールで `designer` エージェント (`.claude/agents/designer.md`) を起動し、UI を検証:

1. **レイアウト**: iPhone SE / Pro Max 対応
2. **Dynamic Type**: セマンティックフォント、テキストサイズ耐性
3. **統一性**: コンポーネントサイズ、カラー、タップ領域
4. **インタラクション**: 空状態、ローディング、エラー状態

問題があれば修正し、最終結果をユーザーに報告する。

---

## フェーズ 6: 完了報告

全工程が完了したら、以下のサマリを出力する:

```markdown
## Feature Complete: [機能名]

### 変更ファイル一覧
（変更したファイルと変更内容の概要）

### QA 結果
| カテゴリ | 状態 | 問題数 |
|----------|------|--------|
| P0: データ安全性 | OK | 0 |
| P1: 機能整合性 | OK | 0 |
| P2: コード品質 | OK | 0 |
| P3: 設計 | OK | 0 |

### デザインレビュー結果
（検証結果のサマリ）

### 残課題
（あれば記載）
```
