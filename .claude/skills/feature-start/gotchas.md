# Feature Start: よくある失敗パターン

## 1. PM フェーズをスキップして実装に入る
要件が曖昧なまま実装すると手戻りが発生する。必ず PM → 設計 → 実装 → QA → デザインの順序を守ること。

## 2. 既存機能へのデグレ確認不足
新機能追加時に既存画面の動作確認を怠る。特にホーム画面、タスクリスト、カレンダーの3画面は必ず確認すること。

## 3. ビルド確認なしでの次フェーズ移行
実装フェーズ完了時に `xcodebuild build` でビルド成功を確認すること。エラーを放置して QA に進むと無駄な工数が発生する。

## 4. 全ターゲットでのビルド確認漏れ
メインアプリだけでなく Widget と ShareExtension のビルドも確認すること。Model 層の変更は全ターゲットに影響する。

## 5. ユーザー承認なしの大規模変更
アーキテクチャ変更やデータモデル変更はユーザー（開発者）の承認を得てから実行すること。
